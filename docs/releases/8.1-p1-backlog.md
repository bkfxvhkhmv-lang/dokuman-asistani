# BriefPilot 8.1 — Production Readiness Backlog

## Scope

- `8.0` internal RC / TestFlight is **not blocked** by the items below
- public Reply Assistant rollout remains **blocked** until the required `8.1` gates are closed

## A) 8.1 Limited Beta P0

These items are mandatory before a controlled / limited Reply Assistant opening beyond the current internal RC.

### LB-P0-01 — Feature flag + controlled rollout

- feature flag
- controlled rollout plan
- explicit exposure scope

### LB-P0-02 — Real document validation

- `20–30` real documents
- OCR → category → template path verified
- include high-risk and low-risk examples

### LB-P0-03 — Critical template lawyer review

Minimum legal review set:

- `bussgeld_general_einspruch_005`
- `finanzamt_einspruch_fristwahrung_002`
- Jobcenter templates
- `schufa_selbstauskunft_001`
- `inkasso_zahlung_nachweis_003`

### LB-P0-04 — Production monitoring / error logging

- runtime error visibility
- route / failure observability
- ability to detect misrouting or render failures quickly

### LB-P0-05 — Kill-switch / remote disable

- remote disable path
- rollback plan
- documented emergency response path

### LB-P0-06 — OCR image retention / data privacy policy

- retention behavior documented
- privacy expectations clarified
- handling of OCR images and derived text explicitly reviewed

### LB-P0-07 — Scope isolation

Limited beta must expose only the new Reply Assistant flow.

Legacy surfaces are **not part of the limited beta scope**:

- `YanıtSablonlariModal`
- `EinspruchSheet`
- legacy `Share`
- legacy `PDF`

## B) Public Rollout P0

These items are mandatory before full public Reply Assistant exposure.

### PR-P0-01 — All Limited Beta P0 items

- every `LB-P0-*` item above must already be closed

### PR-P0-02 — Production reply-surface alignment

All production reply surfaces must be classified and aligned:

- new Reply Assistant copy-only flow
- `YanıtSablonlariModal`
- `EinspruchSheet`
- any legacy reply-template surface
- `Share`
- `PDF`
- export policy

Each surface must be explicitly:

- hidden
- feature-flagged
- renamed as legacy
- or aligned with copy-only policy

### PR-P0-03 — Forbidden wording scan

Run a full wording scan across:

- app UI
- store copy
- push / notifications
- help / docs / release copy

Forbidden or legally risky wording includes:

- `rechtssicher`
- `garantiert`
- `Anwaltsqualität`
- `anwaltlich geprüft`
- `automatisch einlegen`
- `automatisch einreichen`
- `BriefPilot erledigt`
- `BriefPilot versendet`
- `BriefPilot prüft verbindlich`
- `Ihr Einspruch ist fertig`

### PR-P0-04 — Store wording RDG-safe review

Before public rollout:

- App Store wording review
- Play Store wording review
- no legal-guarantee framing
- no misleading automation claims
- no implication that BriefPilot files or sends legal actions on behalf of the user

### PR-P0-05 — Android real-device smoke

Public rollout requires Android real-device smoke for:

- OCR entry
- OCR analyze path
- Reply Assistant entry
- high-risk and low-risk flows

## C) P1 (should be done in 8.1)

- typography & font hierarchy
- stronger `Was passiert jetzt?` guidance
- entry micro-copy
- copy success polish
- error / empty / loading polish
- user testing with `5–8` users for controlled beta confidence
- `inferReplyCategory` unknown fallback

## 8.5 / Later

- lawyer-approved badge
- template audit trail
- broader legal review program
- disclaimer A/B testing

## Release policy

- `8.0` internal RC / TestFlight may proceed
- limited beta opening requires `8.1 Limited Beta P0`
- public rollout requires all `Public Rollout P0` items to close
