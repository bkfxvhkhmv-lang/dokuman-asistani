# BriefPilot 8.1 — Production Readiness Backlog

## Scope

- `8.0` internal RC / TestFlight is **not blocked** by the items below
- public Reply Assistant rollout is **blocked until all 8.1 P0 items close**

## 8.1 Production P0

### P0-01 — Feature flag / controlled rollout

Reply Assistant must not be public by default without:

- feature flag
- controlled rollout plan
- emergency kill-switch path

### P0-02 — Real document validation set

Validate OCR → category → template on a real document set before public rollout.

Target:

- `20–30` documents
- controlled real-world samples
- supported high-risk and low-risk categories

### P0-03 — OCR → category → template logging + fallback

Public rollout requires:

- logging for OCR/category/template routing
- visibility into unknown / unsupported classification outcomes
- safe fallback behavior when category inference is uncertain

### P0-04 — Critical template legal review

At minimum, legal review is required for:

- `bussgeld_general_einspruch_005`
- `finanzamt_einspruch_fristwahrung_002`
- Jobcenter templates
- `schufa_selbstauskunft_001`
- `inkasso_zahlung_nachweis_003`

### P0-05 — Android real-device smoke

Public rollout requires Android real-device smoke for:

- OCR entry
- OCR analyze path
- Reply Assistant entry
- high-risk and low-risk template flow

### P0-06 — Production monitoring / error logging

Public rollout requires:

- production monitoring
- runtime error visibility
- basic route/failure observability

### P0-07 — Kill-switch / remote disable

Reply Assistant public exposure requires a remote-disable or kill-switch plan.

### P0-08 — Forbidden wording scan

Run a full wording scan across:

- app UI
- store copy
- push / notifications
- help / docs / release copy

Forbidden or legally risky wording includes:

- `rechtssicher`
- `garantiert`
- `Anwaltsqualität`
- `anwaltlich geprüft`
- `automatisch einlegen`
- `automatisch einreichen`
- `BriefPilot erledigt`
- `BriefPilot versendet`
- `BriefPilot prüft verbindlich`
- `Ihr Einspruch ist fertig`

### P0-09 — Production reply surface alignment

All production reply-template surfaces must be classified and aligned before public rollout:

- new Reply Assistant copy-only flow
- legacy reply-template surfaces
- `YanıtSablonlariModal`
- `EinspruchSheet`
- `Share`
- `PDF`

Each surface must be explicitly:

- hidden
- feature-flagged
- renamed as legacy
- or aligned with copy-only safety policy

This item is a public-rollout P0 even if it is not a blocker for `8.0` internal RC.

### P0-10 — Store wording RDG-safe review

Before public rollout, review App Store / Play Store text for RDG-safe wording:

- no legal-guarantee framing
- no misleading automation claims
- no implication that BriefPilot files or sends legal actions on behalf of the user

### P0-11 — Disclaimer layer design

Every public reply surface must include appropriate disclaimer layers without overwhelming the user.

Minimum principle:

- persistent `Nur Entwurf · Kein Rechtsrat`
- high-risk amber warning where applicable
- copy-only / no-send guidance
- user responsibility reminder

This item is accepted as a production P0, but UX/tone must be handled carefully to avoid disclaimer overload.

### P0-12 — Frist responsibility

Every relevant reply flow/template must make clear:

- `BriefPilot berechnet keine Fristen.`
- the user is responsible for deadline checking

### P0-13 — RDG advisor opinion

Obtain explicit legal/RDG positioning for:

- product framing
- disclaimer adequacy
- copy-only assistant scope
- public rollout boundaries

## 8.1 P1

- font hierarchy / spacing polish
- stronger `Was passiert jetzt?` guidance
- entry point micro-copy
- copy success polish
- error / empty / loading state polish
- moderated user testing with `5–8` users for controlled beta confidence

## 8.5 / Later

- lawyer-approved badge
- template audit trail
- broader legal review program
- disclaimer A/B testing

## Release policy

- `8.0` internal RC / TestFlight may proceed
- `8.1` is the production-readiness gate
- public Reply Assistant exposure must remain blocked until all Production P0 items are closed
