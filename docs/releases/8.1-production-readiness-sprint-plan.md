# BriefPilot 8.1 — Production Readiness Sprint Plan
**Oluşturuldu:** 2026-06-05
**Branch:** feature/8.1-production-readiness
**Durum:** Planning — approved, implementation not started

---

## Önemli Çerçeve

**8.1 = Safety & Controls Sprint. Feature sprint değil.**

Hedef: Reply Assistant'ı ≤20 kullanıcıya limited beta olarak güvenle açmak.
Public launch değil. Broader rollout değil.

**Public Rollout, 8.1 bitişiyle açılmaz.** Public Rollout P0 gate'leri ayrıdır — bkz. "What Moves to 8.5" ve P0 gate listesi.

---

## Sprint Goal

`__DEV__` guard'ını production-grade kontrollerle değiştir — remote feature flag, kill-switch, consent, monitoring ve real-document validation — böylece ≤20 kullanıcılık kontrollü bir beta cohort'u Reply Assistant'a yasal ve veri gizliliği riski olmadan erişebilir.

---

## Kritik Kararlar (Approved)

### 1. Remote Config zorunlu — AsyncStorage tek başına yeterli değil

**Karar:** 8.1 limited beta için feature flag ve kill-switch **remote config** üzerinden çalışmalıdır.
AsyncStorage yalnızca local debug override olarak kullanılabilir.

**Neden:** Kill-switch'in anlamı merkezi ve anında kapatmaktır. Sadece cihaz içi (AsyncStorage) flag olursa, uygulama güncellenmeden veya kullanıcı uygulamayı açmadan kapatma yapılamaz. Bu, limited beta için kabul edilemez bir risktir.

Önerilen: Firebase Remote Config, LaunchDarkly veya eşdeğer bir remote config servisi.

### 2. Lawyer review ve OCR retention policy beta gate'inin parçasıdır

Bu iki kalem code task değildir ama **limited beta açılmadan "done" olmaları zorunludur:**
- Kritik template lawyer review (en az: bussgeld + finanzamt şablonları)
- OCR image retention / data privacy policy kararı ve dokümantasyonu

Bunlar "external parallel" değil, **beta go-live blocker**'dır.

### 3. Classifier rewrite yasak — küçük mapping/fallback fix'leri serbest

`inferReplyCategory` için broad classifier rewrite veya yeni regex set ekleme 8.1 kapsamı dışındadır.

Ancak real-document validation (Task 4) sırasında bulunan küçük mapping veya fallback hataları fix edilebilir. Kriter:
- Fix, mevcut kategori mantığını bozmaz
- Fix, yeni Behörde tipi eklemez
- Fix, validasyon sırasında tespit edilen ve kayıt altına alınan somut bir FAIL'e yanıt verir

## Implementation Tasks

### Task 1 — Feature Flag (replaces `__DEV__` gate)

**Öncelik:** İlk. Her şey bunun üstüne kurulur.

**Ne yapılır:**
- `useDevReplyAssistantForAppeal` içindeki `__DEV__` kontrolü kaldırılır
- Flag key: `reply_assistant_beta_enabled`
- Remote config'den okunur (Firebase Remote Config veya eşdeğeri)
- Default: `false` — tüm kullanıcılar için kapalı
- AsyncStorage: yalnızca local debug override (internal cihazlarda test için)
- Per-device veya per-user override mümkün olmalı (internal testers için)

**Acceptance criteria:**
- Flag `false` → Reply Assistant UI'a ulaşılamıyor, legacy sheet etkilenmiyor
- Flag `true` → 8.0 smoke ile aynı routing çalışıyor
- Flag app rebuild olmadan değiştirilebiliyor
- Cihazda test: toggle on → off → restart → state doğrulandı

---

### Task 2 — Kill-Switch + Production Error Logging

**Öncelik:** İkinci. Beta go-live öncesi zorunlu.

**Ne yapılır:**
- Remote flag `reply_assistant_kill_switch` — `true` olduğunda entry point anında gizlenir (app update gerekmez)
- Kill-switch etkisi ≤5 dakika içinde görünür olmalı
- Sentry (veya mevcut error infra) şu noktalarda unhandled error yakalar:
  - `ReplyAssistantDevPreview`
  - `inferReplyCategory`
  - `getReplyTemplateCandidates`
- Reply assistant içindeki crash host screen'e yayılmamalı (catch boundary)
- Alert eşiği beta öncesi tanımlanmalı: örn. error rate >%2 → bildirim

**Acceptance criteria:**
- Kill-switch staging'de test edildi: etkinleştirildi, UI bir sonraki foreground'da kayboluyor
- Sentry'de test hatası görünür (kasıtlı throw)
- Document detail screen reply assistant hatalarında çökmüyor

---

### Task 3 — First-Use Consent Screen

**Öncelik:** Üçüncü. Task 1 ile paralel geliştirilebilir. Beta go-live öncesi zorunlu.

**Ne yapılır:**
- Kullanıcının ilk Reply Assistant girişinden önce bir kez gösterilen consent modal
- AsyncStorage key: `reply_assistant_consent_given`
- Kabul → consent kaydedilir, devam edilir
- Reddetme → document detail'e dönülür, değişiklik yok

**Zorunlu içerik:**
- "Textbaustein-Werkzeug, kein Rechtsrat" — eşdeğer açık ifade
- Forbidden wording kesinlikle bulunmaz: `rechtssicher`, `garantiert`, `anwaltlich geprüft`, `automatisch einreichen`
- Reddetme butonu kabul ile eşit görünürlükte (dark pattern yok)

**Acceptance criteria:**
- İlk kullanımda gösteriliyor, sonrasında bir daha gösterilmiyor
- Reddetme path'i: kısmi state kalmıyor
- 4 disclaimer katmanı ilk kullanımda mevcut (consent = Katman 1)
- Forbidden wording audit: PASS

---

### Task 4 — Real Document Validation (20–30 Belge)

**Öncelik:** Dördüncü. Task 1 ve 2 tamamlandıktan sonra — stable flagged build gerekli.

**Ne yapılır:** Bu bir kod task'ı değil, yapılandırılmış test oturumudur. Detaylar: `docs/releases/8.1-real-document-validation-matrix.md`

**Kapsam:**
- Minimum 20 belge, hedef 30
- P0 kategorilerin tamamı kapsanır: Bußgeldbescheid, Finanzamt, Jobcenter, Schufa, Inkasso, Fallback
- Tüm belgeler anonimleştirilir (DSGVO) — gerçek isim, IBAN, Aktenzeichen içermez
- Sonuçlar matrix formatında kayıt altına alınır
- Validation sırasında bulunan FAIL → issue olarak açılır

**Acceptance criteria:**
- High-risk path (bussgeld Einspruch, Finanzamt): 0 crash, 0 amber eksik, 0 yanlış template — sıfır tolerans
- P0 kategoriler genel: ≥%90 PASS
- Tüm FAIL'lar triaged: fix edilmiş veya erteleme gerekçesi yazılmış
- Sonuç dokümanı `docs/audits/` altına commit edilmiş
- Classifier fix gerekirse: yalnızca bu validation'dan çıkan somut FAIL'e yanıt veren, küçük mapping/fallback fix'i

---

### Task 5 — Analytics + Drop-Off Tracking

**Öncelik:** Beşinci. Beta day 1'den itibaren aktif olmalı.

**Ne yapılır:**
- Reply assistant adımları event ile işaretlenir

**Eventler:**
```
reply_assistant_opened
reply_assistant_fill_started
reply_assistant_preview_viewed
reply_assistant_copy_tapped
reply_assistant_exited_without_copy
```

- Per-category dimension: `{ category: 'bussgeld' | 'finanzamt' | ... }`
- PII kesinlikle event payload'da bulunmaz: belge metni, extract edilen alan değerleri, absender adı
- Mevcut analytics pipeline'a bağlanır (yeni infra gerekmez)
- Fill→Preview ve Preview→Copy drop-off oranı kategoriye göre görünür

**Acceptance criteria:**
- 5 event staging run'da tümü tetikleniyor
- Event payload'larda PII görünmüyor (bir oturum audit edildi)
- Funnel, kategoriye göre sorgulanabiliyor
- Kill-switch aktifken analytics event tetiklenmiyor (ghost event yok)

## Task Sırası / Bağımlılıklar

```
Task 1 — Feature Flag
  └─► Task 2 — Kill-switch + Monitoring    (flag infra'sını genişletir)
  └─► Task 4 — Real-doc Validation         (stable flagged build gerekli)
  └─► Task 5 — Analytics                   (live flow instrumentation)

Task 3 — Consent Screen
  → bağımsız, Tasks 2–5 ile paralel geliştirilebilir
  → herhangi bir harici kullanıcı Task 1'i görmeden önce tamamlanmalı

Paralel / Harici (code değil, beta gate blocker):
  → Lawyer review: bussgeld + finanzamt şablonları minimum
  → OCR image retention / data privacy policy kararı + dokümanı
  → Incident response plan: sorumlu kişi, kill-switch prosedürü, iletişim şablonu

Beta Go-Live Gate:
  Task 1–5 DONE
  + 3 harici kalem DONE
  + Ready for Limited Beta checklist eksiksiz PASS
```

  [ ] Tüm FAIL'lar triaged: fix edilmiş veya erteleme gerekçesi yazılmış
